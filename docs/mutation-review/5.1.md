## The nightly hook score understates coverage

The nightly run (and `vitest.mutation.config.ts`'s default) only runs `src/hooks/**/__tests__` and
`src/utils/**/__tests__`, so a hook exercised only through a component test (`PotWithdrawalForm`,
`PotDepositForm`, `ManagePotsDialog`, the account and operation routes) counts as untested. Run
with every web test (`STRYKER_TEST_INCLUDE='src/**/*.test.ts,src/**/*.test.tsx'`), the same eleven
hooks score 80.3%, not about 2%. The 64.0% nightly figure for all hooks is low for the same reason.
Later 5.x slices should be picked and measured with every test included; the nightly ranking is
only a starting list. Including every test makes a run slow (about 80 minutes for these eleven
files), so the nightly job keeps its narrow set.

The new tests are hook tests (`renderHook`) in `src/hooks/__tests__`, so the nightly run now
counts them too.

## Gaps closed

- **`usePotWithdrawalForm`** (14 tests): changing the pots account clears the pot; clearing the
  bank clears the category, changing to another bank keeps it; a whitespace-only date or
  description is refused and the description is saved trimmed; the date is remembered for the next
  withdrawal; a second submit while saving and a submit before the pots load are ignored; a failed
  save stops saving and shows the fallback message; an account with no active pot asks for one;
  an edit opens unlocked with its bank and category, blanks for missing ones and the first active
  pot by default; opening from a bank locks it and picks the first pots account; a pots load
  failure is reported.
- **`usePotDepositForm`** (10 tests): a single funding line follows the amount until edited, and
  several lines are left alone; an edit opens with its funding lines (or as "no bank" with one
  blank line) into the pot it named; removing a line; whitespace-only date and description;
  trimmed description and remembered date; failed save; pots load failure; nothing reported
  before opening.
- **`useManagePots`** (6 tests): a name that only gains surrounding spaces is unchanged, switching
  a pot off is a change; a name or split error blocks saving; removing a new pot removes only that
  one; a failed save shows its message.
- **`usePortfolioDeletion`** (3 tests): the failure message; a new delete clears the old error;
  success clears the selection and reloads.
- **`useRowEditRoute`** (4 tests, new file): the row named by `?edit=` opens once and the parameter
  is removed in place (a replace, not a new history entry); the same row opens again when named
  again; an unknown row is reported unavailable; nothing opens without the parameter.

## The 16 still undetected, all reviewed

- **Wording** (5): delete and load error texts in `useAccountRowDelete` and `useAccounts`, and the
  pot name and currency fallbacks used only inside the withdrawal overdraft message.
- **Equivalent** (3): `usePotWithdrawalForm`'s pot id when no form is open (`values` is null then);
  `useRowEditRoute`'s `found` when there is no edit key (no row has a null key anyway) and its
  `useCallback` dependency list (`setSearchParams` keeps its identity).
- **Accepted** (8): the withdrawal pots account when no account has pots (opening from a bank is
  not offered then), and a second overdraft confirmation while the first is saving;
  `useFormErrorFocus`'s focus rules (3), which need a rendered form; `useOperationRoute`'s income
  lookup and re-open guard (2); `useColumnFilterAddress` writing filter values sorted, which only
  keeps the address stable.
