Measured against 13 test files: the five forms' own tests, the hooks behind them, the Income tab,
the account screen and the accounts page. The run took 70 min. After the new tests every reported
survivor was replayed (the mutant applied to the source and the form's own test file run against
it): 9 still survive, each reviewed below, and the other 50 are caught.

## Gaps closed (22 test cases added, 5 extended)

- **Every form** (3 added, 2 extended where Enter was already tested): submitting with Enter calls
  the save without the browser also submitting the page.
- **Expense** (3 added): Date and Value are required only while the charge's statement is unpaid; a
  settled charge paid through a round-up bank offers no round-up; changes to the date, payment
  source and round-up reach the form.
- **Income** (8 added, 1 extended): ticking Split to pots reports `true`; date and gross value
  changes reach the form; a save error stays out of the alert while a funding line carries its own
  error; the Pots account picker is enabled once the accounts are ready, and stays disabled while
  they failed to reload; with no Pots account stored there is no "Selected Pots account" option, and a
  stored one no longer listed is kept under that name; the load failure warning shows only while the split is
  ticked, and the failure hint does not also say there is no active Pots account.
- **Transfer** (4 added): no same-bank error before either bank is chosen; To always offers
  "Select a bank" and From only until one is chosen; the date, amount and note changes reach the
  form; the amount is labelled plainly unless both currencies are known.
- **Pot deposit** (3 added, 1 extended): the pot picker is hidden while splitting and the
  preview's amount column names the currency; "Loading pots…" shows until the pots arrive, with no error,
  and goes once they fail; unticking "No bank" brings the funding lines back; Date and Description
  are marked invalid with their own errors.
- **Pot withdrawal** (1 added, 1 extended): the amount is labelled without a currency until the
  pots arrive; a blank category adds no "Saved category" option.

## Still undetected

All reviewed:

- **Equivalent** (7):
  - The expense form checks bank mode twice before showing Round-up, in the round-up flag and in
    the condition that renders it; either one replaced by `true` leaves the other (2).
  - The transfer's same-bank check tests both banks are chosen and then that they are equal: with
    one blank they already differ, so replacing either blank test, or its `''`, changes nothing (4).
  - The income source's gross value fallback name (1): no listed source has that name either way.
- **Accepted** (2): the withdrawal's overdraft dialog message fallback, read once the message is
  cleared, so it shows only during Fluent's close animation, which jsdom does not run; and the
  transfer's received amount defaulting to text instead of `''`, which the account screen never
  relies on (it always passes the amount) and which a number input shows as empty, differing only in
  the DOM `value` attribute.

## Noticed

- The overdraft dialog loses its message while it fades out, as the card statement's unmark dialog
  does (slice 8.4): the message is cleared as the dialog closes. The two can be fixed together.
- The expense form checks bank mode both in its round-up flag and where it renders the field; one
  of the two can go.
