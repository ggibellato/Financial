# 9.2 Api controllers (78.7% → 95.6%)

Slice notes for [the mutation review](mutation-review.md). The tracker table row and log line
are updated in a separate tracker PR.

| before | after | added | removed | equivalent | accepted | unreachable | ConfigureAwait |
|---|---|---|---|---|---|---|---|
| 78.7% (248 of 315) | 95.6% (301 of 315) | 1 | 0 | 1 | 1 | 6 | 6 |

Files: every controller under `Financial.Api/Controllers` (42 files, 3060 lines). All but one gap
was closed by tightening an existing test. Timeouts are counted as detected.

Gaps closed:

- **Null request-body guards** (45 mutants, most of the gap): every `if (request is null) return
  BadRequest();` survived, because without it the null reaches the service, which throws
  `ArgumentNullException`, which the exception middleware also maps to 400.
  `EmptyBodyEndpointsTests` now also requires the 400 to come from before any service, as its own
  message says (rejected "rather than reach a service"): no exception `detail` (the middleware's
  mark) and no validation error on a route parameter (a placeholder the route could not bind). A
  validation error on the body itself is fine: `mark-paid` takes a non-nullable body, which
  `[ApiController]` rejects on its own. Route placeholders now come from the action parameter's
  type, so `PUT tax-rules/{id}` (a `Guid` with no route constraint) reaches its guard instead of
  failing model binding on `x`.
- **Dividends**: an explicit exchange is used rather than the configured default (the summary test
  sent `BVMF`, which is also the default).
- **Asset prices**: the asset class and valuation method are parsed case-insensitively (two existing
  stub tests now send them in lower case).
- **Tax workbook** (new test): a request with no tax year is rejected (the `taxYear ?? string.Empty`
  fallback had no coverage; with any non-blank fallback the request would return 200).
- **Calendar callback**: the landing page says "Connected!" on success and "Connection not
  completed" when consent is declined.

The 14 still undetected, all reviewed:

- **`ConfigureAwait`** (6).
- **Unreachable over HTTP** (6): the blank-ticker guards in `DividendsController` (2), the blank
  broker or portfolio guards in `CorporateActionsController` and `TransactionsController` (2), and
  the calendar callback's `?? "Please try again."` fallback (2: `CalendarIntegrationService` always
  sets an error message on failure). A whitespace route value is bound as null, so `[ApiController]`
  returns 400 before the action runs. Production note: these guards are dead code.
- **Accepted, not pinned** (1): the calendar success page's "You can close this tab" text.
- **Equivalent** (1): `TaxWorkbookController`'s `jurisdiction ?? string.Empty` (any fallback fails
  the jurisdiction parse, so the result is 400 either way).
