## Gaps closed (10 test cases)

- **Calendar connection**: loading shows from the first render; the status stays shown while a
  retry after a failed refresh reloads; focus does not re-check the status unless connecting, and
  stops re-checking it once connected; a disconnect shows as running and clears an earlier
  disconnect error.
- **Reporting currency**: loading shows from the first render; changing the currency while
  conversion is off keeps it off; a currency chosen before the setting has loaded turns conversion
  on; a save shows as running and clears an earlier save error.
- **Calendar sync statuses**: loading shows from the first render. The resync test now checks the
  other card's last sync time, which the old state check could not tell apart (both cards ended
  synced).

## Still undetected

All reviewed:

- **Equivalent** (13):
  - **Hook dependency lists** (9): the fetch dependency lists filled with a constant (3 hooks), the
    `useCallback` lists of `connect`, `disconnect`, `resyncCard`, `save` and `setEnabled` emptied
    or filled (everything they list is stable), and the sync status poll's effect list filled with a
    constant.
  - **Keeping data while reloading** (2, sync statuses and reporting currency): neither refreshes
    after loading, so a retry follows only a failed first load, when there is no data to keep.
  - **Sync status** (2): the "cancelled" flag never set, or ignored; React drops a state update
    after unmount anyway.
- **Wording** (6): the load fallback messages (3), and the disconnect, resync and save fallback
  messages.
