Measured against every test that reaches the four hooks through its imports (as in [5.1](5.1.md)),
not the nightly report's hook-only test set. A second Stryker run measured the tests before the
review; the review then dropped two of them (see below), and the after figures above remove the two
mutants only those tests killed. Every other mutant was checked again by hand.

## Gaps closed (7 test cases)

- **Calendar connection**: loading shows from the first render; focus does not re-check the status
  unless connecting; a disconnect shows as running and clears an earlier disconnect error. The
  existing focus test now also checks that focus stops re-checking once connected.
- **Reporting currency**: loading shows from the first render; changing the currency while
  conversion is off keeps it off; a save shows as running and clears an earlier save error.
- **Calendar sync statuses**: loading shows from the first render. The resync test now checks the
  other card's last sync time, which the old state check could not tell apart (both cards ended
  synced).

The existing "loading on mount" checks, which read the state after the fetch had started, are gone
from all three files; the first-render tests replace them.

## Still undetected

All reviewed:

- **Equivalent** (15):
  - **Hook dependency lists** (9): the fetch dependency lists filled with a constant (3 hooks), the
    `useCallback` lists of `connect`, `disconnect`, `resyncCard`, `save` and `setEnabled` emptied
    or filled (everything they list is stable), and the sync status poll's effect list filled with a
    constant.
  - **Keeping data while reloading** (3, one per loading hook): the Integrations and Reporting
    Currency pages show only the loading or error state while either is set, so the data kept
    during a retry is never shown.
  - **Reporting currency** (1): turning conversion on for a currency chosen before the setting has
    loaded (`enabled ?? true`); the page shows no currency choice until the setting has loaded.
  - **Sync status** (2): the "cancelled" flag never set, or ignored. The effect runs once in
    production; only development's double mount can leave a second poll in flight.
- **Wording** (6): the load fallback messages (3), and the disconnect, resync and save fallback
  messages.

## Noticed

- `useReportingCurrency` sends `enabled: true` when the currency is set before the setting has
  loaded. No page can do that today, so the fallback is dead code; removing it is a product change
  for its own PR.
