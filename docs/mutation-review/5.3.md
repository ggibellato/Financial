File: `useAccountActionForms`, which runs the account screen's create, edit, move and operation
forms and makes opening one close the others. Measured against the tests that reach it
(`useAccountActionForms.test.ts` and `AccountScreenPage.test.tsx`), as [5.2](5.2.md) left it.
The mutant count moved from 305 to 304 between runs (the source did not change; Stryker's own
count of the ignored ones did).

## Gaps closed (20 tests)

- **Opening another action closes** an open pay-bill, pay-statement or credit-refund form (each
  form's `if (form.isOpen) form.cancel()` guard turned to `false` survived) and a move form.
- **Credit refund label**: on a bank the action is "receive card credit", on a card account
  "refund credit to bank".
- **Row edit and row move** close an open action first.
- **Edited row tracking**: a create action opened after a row edit is not closed when that row is
  closed; a moved row's form closes with its row, not with another row's.
- **Operations**: opening one closes an open action; its form stays open when the rows refresh
  (operation rows are not in the row list); following the same operation focuses its form instead
  of leaving it, and following another one, or one while none is open, navigates.
- **Removed row**: an edited row's form closes when the refreshed rows no longer hold it.
- **Focus** (found by the simplify review, which showed these were testable through the hook's
  form area): moving a row being edited focuses the form again; closing a form returns focus to its
  opener only when focus was on the page body; after a save, focus moves to the next entry once
  and not again on the next render; following the open operation focuses its form; an account
  that has not loaded is not treated as a card; a pots account's deposit switching to the income
  form's deposit focuses the form again (the `:income` key suffix).

The test now also mocks `getPayableStatements`, `getAccountStatements`, `getCardsInCredit` and
`getPots` (left pending), which the pay-statement, move, credit-refund and deposit forms load when
they open.

## Still undetected

The last Stryker run (93.1%, 283 of 304) was before the last six tests. A full run takes over
two hours here, so those six were checked by hand instead: each mutation below was applied to the
source and the test file run against it.

- Killed by hand, from that run's survivors (5): the row edit or move key emptied, the `:income`
  key suffix emptied, the focus fallback turned to `true`, the next-entry focus flag never reset,
  and `isCard` defaulting to `true`. That puts the score at 94.7% (288 of 304). The save test
  now also checks that focus first lands on the next entry (removing that focus call fails it). The corrected "follow the open operation"
  test also now fails when that focus call is removed (it passed without it before).

What is left, all reviewed:

- **Equivalent** (13): each `if (form.isOpen) form.cancel()` guard turned to `true` (12: cancelling
  a closed form changes nothing); one of the two string mutants Stryker left at the row key (line
  177). Emptying the whole key is now killed, while emptying the `'move'` or `'edit'` label inside
  it leaves the two keys different, so the form remounts either way (checked by hand). Which of
  Stryker's two mutants is which needs a full run to name.
- **Wording** (2): the income and balance adjustment saved messages.
- **Accepted** (1): the next-entry flag's start value. In these hook tests the form area is attached
  after the first render's effects, so a flag that starts `true` focuses nothing; on the real
  screen the form area exists on the first render, so this is only provable through a component
  test.
