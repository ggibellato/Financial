## Gaps closed (41 tests)

- **Load failures**: the asset, broker and portfolio load messages for transactions and credits,
  and transaction types reported as not loaded until they arrive.
- **Incomplete nodes**: an asset or portfolio node missing its names loads nothing, and selecting
  one after an asset clears that asset.
- **Charts**: an asset is charted from its own transactions and a broker from its summary; monthly
  credit totals are ordered by year then month; the period keeps credits from its first day; the
  net-invested range starts at the earliest transaction even when it is listed first.
- **Selection keys**: separate keys for an asset, a portfolio and a broker, with and without names.
- **Validation**: whitespace-only dates, zero values, zero quantity and unit price for a type that
  moves quantity, non-positive shares, and a specific-ID sale with no lot allocated.
- **Payloads**: a type with no quantity effect saves quantity and unit price 0; a zero lot
  allocation is left out; fees, withheld and intermediation fee are sent as typed, and as 0 when
  whitespace; whitespace-only shares are sent as no shares; the save fallback message.
- **Delete**: the edit form stays open when a different row is deleted; nothing is deleted while a
  portfolio is selected.
- **Expense form**: no round-up for a non-numeric or zero value or a non-round-up bank; a create
  form opens with no round-up; editing loads a card charge's card and invoice month, and a bank
  expense with blank card fields; a round-up is still suggested while editing an expense saved
  without one; the invoice month follows the date for a charge on its default month; cancel and
  an edit save leave edit mode; the default category when the remembered one is gone; no bank or
  category when none is active; an edit can clear the description.

## Still undetected

The last Stryker run (90.0%, 555 of 617) was before the last eleven tests. A full run takes over
an hour here, so the rest was checked by hand: each mutation was applied to the source and the
hook's test file run against it.

- Killed by hand with tests already in that run (9, report quirk): the delete guards and the
  "deleted row was being edited" conditions in `useTransactions` and `useCredits`, the asset-node
  conditions, the quantity-effect lookup, the lot-allocation check, and `isEditing` after a save.
- Killed by the last eleven tests (11): the broker chart source, the withheld, fee and shares
  parsing, the reset for an incomplete node, the no-active-bank and no-active-category fallbacks,
  the invoice month pin, and the round-up a create form opens with.

That puts the score at 93.2% (575 of 617). What is left, all reviewed:

- **Equivalent** (25): `useCallback` and resource dependency arrays (12); the retry counter
  counting down (2); the month key built from `getMonth() - 1` (used the same way on both sides)
  and `<=` when picking the earliest date; `date >= today` when capping a refund date; trimming a
  value that is already rejected as not finite; the card id and round-up suggestion at create
  (no card in bank mode, no bank or value when the form opens; 4); `value <= 0` for a refund
  (a zero expense cannot be saved); the invoice pin for an expense with no invoice month (only read
  in card mode); trimming a card id (ids never hold spaces).
- **Wording** (7): the type-load, save and delete messages in `useTransactions`, and the
  record name and update message in `useExpenseForm`.
- **Accepted** (10): the lot-allocation check at quantity 0 (2; the zero quantity is already
  refused); the invoice month default recomputed in bank mode (the field is hidden and not sent);
  a settled expense's round-up eligibility and its trimmed payment fields (7). A settled expense
  always carries its bank and card, and whether it should resend its round-up is a server rule this
  hook does not own.
