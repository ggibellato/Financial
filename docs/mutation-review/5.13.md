The first of three slices covering the 35 hooks no earlier 5.x slice named, largest first.
Measured against every test that reaches the six hooks through its imports (as in [5.1](5.1.md)):
their own hook tests and the Tax, Admin Accounts, Assets, Annual Summary and Account Screen pages,
the app shell and the payment due banner. The run took 13 min. After the new tests every reported
survivor was replayed (the mutant applied to the source and its own test file run against it): 15
still survive, each reviewed below, and the other 18 are caught.

## Gaps closed (13 test cases)

- **Tax workbook** (3): the tax years stop loading when they fail, and the workbook reports
  loading only while it loads and stops when it fails; a failure without a reason is named for each.
- **Annual summary** (4): loading is reported from the very first render; the shown year's
  figures stay while another year loads; a year that is not a number is ignored; a failed load
  without a reason is named.
- **Admin accounts** (2) and **assets** (2): a failed load and a failed delete without a reason
  are named, the delete saying the account or the asset could not be deleted.
- **Pot transaction edit** (1): a failed save without a reason is named.
- **Payments due** (1): under StrictMode's double load on mount, the answer to the cancelled
  load is ignored, so it neither replaces the shown payments nor restarts the dismiss timer.

## Still undetected

All reviewed:

- **Equivalent** (15):
  - Dependency lists (11): the admin accounts and assets callbacks depend only on
    `mutateAndRefresh`, `updateAccount` and `runPendingMutation`, which `useCrudResource` keeps
    stable for a hook whose refresh mode never changes (7); the tax workbook's retry callbacks, the
    annual summary's `setYear` and the payments due load depend on nothing (4).
  - The tax workbook's retry counters (2): `- 1` changes the count as `+ 1` does, so each retry
    still loads again.
  - The payments due dismiss timer (2): a timer started with nothing to show, or left running
    after a dismiss or unmount, only dismisses a banner that is not showing; only one load can
    dispatch, so a new list of payments never replaces a shown one.
