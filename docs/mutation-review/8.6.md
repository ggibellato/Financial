## Gaps closed (22 test cases added, 6 extended)

- **Annual summary** (9 added): every Category totals column sorts its rows, on data where each
  orders them differently, and the Investments Account and Historic year columns sort theirs; each
  marks its header (`aria-sort`); cells carry the label the stacked layout shows (Category or
  Account on rows, Total on totals, the month on values); both filterable tables take focus without joining the tab order; filtering out every
  category says no row matches across the whole row, and marks the filter as active; the Historic
  spacer rows span every year column; with no history there is no totals footer.
- **Mensais** (4 added, 1 extended): editing a UK bill names that bill; saving an edit returns
  focus to the Edit it was opened from; the expense prompt is disabled while it marks the bill
  Paid; a bill's status menu is disabled while its status changes, the other bill's is not; every
  sortable column marks its header, and Value now sorts data that its order changes.
- **Month transactions grid** (3 added): a running pot operation delete marks only its own rows;
  once a retried load arrives focus moves into the grid; the table takes focus without joining
  the tab order.
- **Income tab** (6 added, 5 extended): Clear filters shows only while filtered, brings every
  income back and focuses the Source filter, and the stacked layout offers it once; an income
  that splits to pots opens with Split to pots ticked and one that does not with it unticked; an
  edit address waits for the incomes before saying the month does not have it, and opening a
  listed income does not warn; closing the form leaves focus alone when it is elsewhere; the table
  takes focus without joining the tab order; missing gross values are named and the Gross and Net
  cells are right-aligned; the loading and empty rows span every column; the deleting row is not
  also told another delete is running.

## Still undetected

All reviewed:

- **Equivalent** (6):
  - The grid's two delete dialogs' label and message fallbacks (4): the delete hook keeps its
    target after the dialog closes, so they are read only before the first request.
  - The grid's Spend list keeping a total with no currency (1): only bankless incomes have no
    currency, they have no category, and Spend shows only while a category filter is on, which
    drops them.
  - Mensais opening a form while a bill saves (1): New bill and every Edit are disabled while it
    saves, so the guard is never reached.
- **Accepted** (5): the grid's row and footer React keys (4), which only warn; and the edited
  bill's label fallback on Mensais (1), read only when the bill being edited is no longer listed
  (see Noticed). A test could catch it, but only by pinning that bug's blank label.

## Noticed

- Deleting the bill being edited on Mensais leaves its edit form open with a blank Bill field:
  Delete is not blocked for it, and neither the delete nor the reload that follows closes the edit.
  Save then does nothing, with no request and no message, until Cancel. Closing the edit when its
  bill is gone (or blocking its Delete) is a small change for its own PR, and would make the label
  fallback unreachable.
- Mensais's guard against opening a form while a bill saves is never reached: New bill and every
  Edit are disabled then, and the reducer ignores the request anyway. It could go.
