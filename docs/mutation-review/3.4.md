# 3.4 CashFlow.Application movements (63.5% → 76.9%)

Slice notes for [the mutation review](mutation-review.md). The tracker table row and log line
are updated in a separate tracker PR.

| before | after | added | removed | equivalent |
|---|---|---|---|---|
| 63.5% (385 of 606) | 76.9% (466 of 606) | 11 | 57 | 25 |

Files: `ExpenseService`, `IncomeService`, `IncomeSourceService`, `IncomeSummaryService`,
`IncomeGroupLookupBuilder`, `CategoryService`, `CategorySummaryService`, `HistoricAverageService`,
`MensaisService`. The tests were four times the size of the services (about 4,700 lines across
280 tests against 1,800 lines of code); this slice removed more than it added and the score rose.

Gaps closed:

- **Spans** with the entity id on every write in the five services that write, failed spans for
  unknown ids and null requests, and success spans on every read (category totals, income summary, salary
  series, historic averages, bills, incomes, income sources).
- **Null requests**: one test per writing service checks every write method throws
  `ArgumentNullException` and records a failed span.
- **Name before lookup**: a blank name for an unknown category or income source is refused for the
  name (a 400), not reported as not found (found by the second simplify pass).
- **Current-month cutoff**: the in-progress month's entries are now dated on the 1st, so the
  `<` vs `<=` boundary is pinned in the category totals, income summary and historic averages
  (expenses and incomes).
- **Historic averages**: the tax difference row (`salary - salaryAfterTaxes`) is checked, and a
  year with no investment category still computes the Resultado (-10 for 120 of groceries).
- **Mensais**: delete and update save; deleting an unknown id throws even when other bills exist;
  a payment expense description over 200 characters is refused (only the Application checks it).

Removed, after the simplify review's altitude check (Domain.Tests own these rules, or another test
in the same file covers the same path):

- 20 `ExpenseServiceTests`: payment-source/card shape, zero value, blank description and every
  round-up rule (`ExpenseTests`), invoice-date defaults, counts-as-tithe default and toggle,
  the mixed category-totals case, the legacy settled description edit (a superset exists), and
  the inactive-card move (`ExpenseTests.MoveToStatement_InactiveCard_Throws`).
- 15 `IncomeServiceTests`: negative net value, missing gross value and description, removing the
  bank (`IncomeTests`), the split rules (`PotDepositTests`, `IncomeTests`), the blank-source theory
  (same path as the unrecognised source), and four split tests that AC tests contain.
- 22 across the other six files: the 2017 eleven-month averages
  (`AnnualAverageMonthsCalculatorTests`), name/due-day/description checks the entities repeat
  (`CategoryTests`, `IncomeSourceTests`, `RecurringBillTests`), the pots-account rules on income
  sources (`IncomeSourceTests`, `CashFlowReferenceResolverTests`), a status update leaving the
  other fields (`RecurringBillTests`), the settled-charge month (covered
  by `ExpenseTests.ReportingDate_SettledCardCharge_IsInvoiceDate`), and duplicates (own-name
  update, fourteen categories, zero series, empty years, lottery rows, unknown bank, inactive
  income sources folded into the mapping test).

Kept on purpose: description length checks (only `DescriptionValidator` has the limit), inactive
category and card lookups, the move-to-another-card's-paid-statement case, future-dated refunds,
and every AC-traited test. The four round-up suggestion tests test a Domain property, but nothing
in Domain.Tests covers those branches; they stay here until a Domain-side test exists.

The 140 still undetected, all reviewed:

- **Log and exception wording** (115).
- **Equivalent** (25): `ConfigureAwait` (19); the service's blank-name checks on category and
  income source create (2, the entities repeat them); `ExpenseService`'s refund check
  `value < 0` vs `<= 0` (the Domain rejects zero) and the `&&` in `NotifyInvoiceChanged` (a card
  expense always has an invoice date); `CategorySummaryService`'s `First` vs `FirstOrDefault` on
  the investment category (both throw when it is missing); `HistoricAverageService`'s
  `TaxDifferenceAverage` (nothing reads it).

Production notes (not changed in a test PR):

- `IncomeAnnualAverageDTO.TaxDifferenceAverage` in `HistoricAverageService` is computed and never
  read; the tax difference row is rebuilt from the salaries.
- `CategorySummaryService` throws when no category is flagged as investment, while
  `HistoricAverageService` treats it as zero.
