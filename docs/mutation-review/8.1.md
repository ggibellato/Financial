The first components slice. The 8.x components were ranked by how much logic they hold (filters,
sorts, validation, calculations), not by size, and these two came first. Measured against every
test that reaches them through its imports: their own tests and the Active Investments, Historic
Investments and Admin Accounts page tests.

Every reported survivor was replayed by hand (the mutant applied to the source and the five test
files run against it) before the new tests, after them, and after the review. Unlike the
[utils](6.1.md), none was a module-level constant, so the Stryker run and the replay agreed before
any test was added. The last review change, to one test, was checked by hand against the one
mutant it kills.

## Gaps closed (23 test cases added, 1 removed)

- **Investment tree** (14 added; the old retry test, which the new one covers, removed):
  - Only the selected portfolio or broker is marked selected, even where names repeat, and only the
    clicked asset, not another of its portfolio or one of the same name elsewhere.
  - The broker and a portfolio are highlighted only while the drag is over them (one table with the
    existing broker test); a drop on either is taken (the browser's default refused) and clears the
    highlight.
  - The drag carries the asset name, and once it ends nothing accepts a drop.
  - The move dialog a drop opens: a drop on the broker offers no existing portfolio (added to the
    existing broker-drop test), Cancel closes it, a closed asset is not offered for archiving, and a
    completed move selects the asset in its new portfolio and shows the reloaded tree.
  - Under a class filter, a portfolio with nothing of that class is hidden while its broker keeps
    another (the broker renders every portfolio; only the portfolio's own check hides it).
  - A broker with no portfolios and an empty portfolio show as leaves while every class is shown.
  - Clicking a broker carries its currency onto the selection (added to the existing broker test).
  - Try again shows loading in place of the error, then the tree.
  - A click-through's pending selection replaces its history entry and scrolls the node to the
    nearest edge (added to the existing router-state test); without one the history is left alone;
    and once consumed it is not applied again when the tree reloads, for example after a move.
- **Account form dialog** (9): a name of spaces is refused; a name and another participant of
  exactly 60 characters are accepted; the chosen currency of a several-currency template is sent;
  switching to a one-currency template takes its currency; editing an account that has a start
  date still requires one; a missing currency alone focuses the first currency box and describes
  only that box with the message; Currencies is marked required; switching between Settlement
  templates keeps the ticked currencies the new one has, and the other participant.

## Still undetected

All reviewed:

- **Equivalent** (42):
  - **Account form dialog** (19):
    - No or unknown template (11): the fallbacks and messages for a missing template, its
      currencies and its capabilities. The admin page opens the form only with the templates
      loaded, and every template name comes from that list.
    - Edit values (4): the fallbacks for another participant, category, opening balance and
      round-up of an existing account. Each is set for every template that shows the field.
    - Opening balance (3): the blank check without trimming and the not-a-number check. The field
      is a number input, which already turns anything else into an empty value.
    - The first currency box's focus reference left off (1): with exactly one invalid field the
      form dialog itself focuses it (with several it focuses the summary), so the new focus check
      pins the dialog, and the description check is what pins this component.
  - **Investment tree** (23):
    - Selection (2): the node-type tests on the portfolio and asset name checks, which the other
      checks already make hold.
    - Tree shape (11): the node-type filters and the `child.nodeType === … ? … : null` branches for
      brokers, portfolios and assets, and the broker keys opened by default. The API builds
      brokers, then portfolios, then assets only.
    - Drops (4): `portfolioName === undefined` in the accept check (a broker passes the other half
      anyway), the leaf asset's tree value, `stopPropagation` on a portfolio drop (the broker's drop
      handler sits on a sibling row), and treating every drop as new-portfolio-only (a drop on a
      portfolio still moves straight there).
    - Load and retry state (6): clearing an error after a successful load or on retry (the loading
      state hides it), the two counters counting down, the scroll guard at mount, and the retry
      callback's dependency list.
- **Accepted** (5): the `: ''` else-branch literals of the row classes (three on the selected class,
  two on the drop-target class), replaced by an empty or a junk class name on rows that are not
  selected or not a target. `aria-selected` carries the selection and the target highlight itself
  is tested.
- **Wording** (2): the account save and tree load fallback messages.

## Noticed

- Several existing tree tests check that a dialog is gone with `queryByRole('dialog')`. Under one
  of the mutants the move dialog stayed open while the text box inside it left the accessible
  tree, so a stronger check (the dialog title) was used here; the older assertions are worth a look
  in a test tidy-up.
- The opening balance's "Enter the opening balance as a number" message can never show: the number
  input empties anything else, so letters read as "Opening balance is required."
