## Gaps closed (24 test cases added, 5 extended)

- **Account screen** (8 added, 3 extended):
  - A deposit named in the address is read only once the form options have loaded, and "Loading
    the deposit or withdrawal…" shows while it loads.
  - An edit address that arrives with a month change waits for that month's rows: the rows of the
    month on screen are kept while the next loads, and acting on them said the row was gone.
  - Focus: the first load leaves focus where it is, and once the reload after a delete has arrived
    a later month change no longer moves focus to the Transactions heading.
  - Counts toward tithe and Split to pots are ticked for a tithe category or a splitting source and
    can be unticked.
  - The transactions region is named by its heading, which takes focus without joining the tab
    order; the tab lists are named Card views and Pots views.
  - A failed first load shows only the error, with no header skeleton beside it.
- **Card statements** (11 added, 2 extended): months sort correctly across a year end and only the
  viewed year's month is marked; Status sorts paid statements by the day paid, an unknown day first;
  the viewed month scrolls into view (`block: 'nearest'`) once the statements arrive; while a payment
  saves every row action is disabled; the unmark dialog's buttons are disabled while it unmarks; a
  failed submit for want of a bank returns focus to Bank; the pay form submits without leaving the
  page; a bank load error shows with Try again, and none shows otherwise; opening the due date form
  on another statement moves focus to its field; the heading takes focus without joining the tab
  order; the bank picker's placeholder and the date field's changes are checked in existing tests.
- **Transactions grid** (5 added): a row with no round-up leaves its cell blank; settlement entries
  sort by note with blanks last; the Category filter offers no value for uncategorised rows (it
  offered "null"); a linked deposit's Edit is disabled while editing is unavailable but a card
  payment's statement link is not; the table takes focus without joining the tab order.

## Still undetected

- **Equivalent** (19):

    the allowed actions (unknown names are dropped by `formActionsOf`), whether it is a card,
    whether it is active, and the currency of the pot and statements forms (5).
  - Text for a confirm dialog that is closed: the row and operation delete dialogs' labels and
    messages (4) and the unmark dialog's message (1).

    tab exists for it to focus, and it clears itself there (1).

    tab moves focus to its own heading after each save before the page's recovery runs, and the
    pots table has no row controls.

    column with its sort accessor, which still pairs.
  - The grid's `default` branch emptied (1), which returns `undefined` either way; the unmark
    dialog's busy fallback (1), read only while it is closed; the pay form's focus effect given a
    constant dependency (1).
