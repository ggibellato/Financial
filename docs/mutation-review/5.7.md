## Gaps closed (18 test cases)

- **Account screen**: a URL that already has a valid month is left alone, and a month that becomes
  invalid later is replaced; filling in the month, changing it, switching tabs and clearing the
  operation all replace the history entry instead of adding one; the operation is read from the
  URL and cleared without losing a month chosen since; Pots are no longer reported once another
  account is selected and still loading. Existing tests now pick an empty month on a month other
  than the current one, and select another account after a month change, so the month carried
  over is the one chosen.
- **Card statements**: loading shows from the first render with a card, and not without one; the
  statements stay on screen while a failed reload is retried; a card change also closes the due
  date form; `closeForms` closes the pay and due date forms; the screen is dirty while the due date
  form has changes; an unmark being sent cannot be cancelled. An existing test now checks that
  choosing a bank leaves the date message.
- **Moving a charge**: `submit` reports the move as sent, and a second submit while saving sends
  nothing; the targets keep their stored statements while a failed reload is retried; nothing is
  reported as having no targets once the form is closed.
- **Card credit refund**: the save message clears when a field changes, when the refund is sent
  again, and when an invalid form is sent after the chosen bank is gone; reopening drops the field
  and save messages; with no card, the account name and currency are empty; in bank mode, the
  credit fills in again once the amount was cleared, and the amount empties when the card is
  unchosen. An existing test now checks that clearing one field's message leaves the others.

## Still undetected

The last Stryker run was the before run. A full run takes about two and a half hours here, so the
new tests were checked by hand: each mutation was applied to the source and the hook's test file
run against it. 45 of the 47 mutants checked are killed, and the two left are counted as
equivalent below. What is left, all reviewed:

- **Equivalent** (20):
  - **Account screen** (2): the empty default for a missing `accountId` (the route always has
    one); the empty default for a missing month parameter (any unparsable value gives the same
    current month).
  - **Card credit refund** (9): the "no banks or cards" conditions (6; the list is null whenever
    the form is closed or loading, and only a reload after a failed save keeps an older list, which
    had the counterpart that was chosen); the opening values before the first `open` (2; `open`
    always sets them before the form shows, and the chosen id is read through the loaded list);
    the bank-mode check on filling in the credit (in card mode the banks carry no credit, so the
    amount filled in would be the same).
  - **Moving a charge** (9): the "no targets" conditions (8; the list is null whenever the form is
    closed or loading for the first time, and a later reload only follows a move to a target that
    was listed); a charge of zero counted as a refund (the domain refuses a zero-value expense).
- **Wording** (2): the pay and unmark fallback messages on the card statements.
