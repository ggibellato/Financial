## Gaps closed (22 test cases)

- **Media query**: a browser with no `matchMedia` reads as no match; a change of query is followed;
  the listener is removed on unmount.
- **Sortable rows**: rows with no value sort last, in their original order, for numbers and dates in
  both directions, wherever they start in the list; a column with no accessor leaves the rows in
  their order.
- **Confirmed delete** (new test file; the hook was covered only through its callers): a delete
  closes and reports the target; a failure keeps the dialog open with the fallback message; the
  earlier failure clears when another delete is requested and while the delete is tried again; the
  dialog cannot be cancelled while the delete runs; cancel deletes nothing.
- **Async resource**: not loading on the first render by default; a response that arrives after the
  selection was cleared is ignored; the selection guard dispatches before any selection has begun
  and drops what an earlier selection dispatches once a newer one begins.
- **CRUD resource**: an older silent refresh that fails after a newer one succeeded is ignored; a
  silent `mutateAndRefresh` settles only once its reload has; a load uses the newest options it was
  given.
- **Column filters**: a column with no accessor reads as unfiltered, whatever selection it is
  handed.

## Still undetected

All reviewed:

- **Equivalent** (33):
  - **Hook dependency lists** (16): the `useCallback` dependency lists emptied or filled in the CRUD
    resource (9) and the async resource (7); everything they list is stable (a reducer's dispatch,
    a ref-backed guard), and the refresh mode never changes for a caller.
  - **Retry and request counters** (3): the retry count going down instead of up (any change
    reloads), in both resources; the request id counting down (only equality with the latest id is
    checked).
  - **CRUD resource** (2): an empty default refresh mode (anything but silent reloads); awaiting a
    refresh that returned nothing.
  - **Sortable rows** (4): three variants of the "both empty" check. V8 sorts by inserting each row
    and always passes the row being placed first, so treating an empty pair as unequal, or an empty
    row as equal to a filled one, leaves the order unchanged; a 100-row list that goes through merge
    passes did not catch them either. Also dividing by the direction instead of multiplying (it is
    1 or -1).
  - **Media query** (2): the `typeof window` checks (the app runs only in a browser).
  - **Column filters** (6): dropping empty entries from a list value (the accessor type allows none
    and no grid returns any); the start set for toggling a column with no accessor (no grid offers
    one); returning the rows unchanged with no active column versus filtering them all through (the
    same rows); the "has a selection" check (only columns with a selection are active).
- **Accepted** (2): sorting values case-insensitively with no sensitivity option, in the sortable
  rows and the column filter values. Default ordering already puts `apple` before `Banana`; the two
  differ only for values that differ only in case, whose order has no meaning.
