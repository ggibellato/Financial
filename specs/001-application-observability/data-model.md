# Phase 1 Data Model: Application Observability

This feature has no business-domain data model — it introduces no new entity in either bounded context's JSON document and does not change `data-cashflow.json`/`data-investment.json`. The "entities" below are the configuration and telemetry-signal concepts introduced by this capability, restated from spec.md's Key Entities section with concrete fields/validation for planning purposes.

## Observability Configuration

The runtime settings that control whether observability is active and where telemetry goes. Bound from the `Observability` configuration section (see [contracts/observability-configuration-contract.md](./contracts/observability-configuration-contract.md)).

| Field | Type | Default | Validation |
|---|---|---|---|
| `Enabled` | bool | `false` | none — always a valid value |
| `Backend` | enum `{Jaeger, Langfuse}` | `Jaeger` | Only read/validated when `Enabled=true`; an unrecognized value MUST fail fast at startup with a clear error (fail loud, not silently fall back — consistent with how `GoogleDriveStorageFactory` already fails fast on missing credentials) |
| `Endpoint` | string (URL) | `http://localhost:4317` | Required (non-empty) when `Enabled=true`; not validated for reachability at startup (FR-010 — unreachable backend must not block startup) |
| `Langfuse.PublicKey` | string | `""` | Required when `Enabled=true` and `Backend=Langfuse`; unused otherwise |
| `Langfuse.SecretKey` | string | `""` | Required when `Enabled=true` and `Backend=Langfuse`; unused otherwise. Treated as a secret — never logged, never included as a span/log attribute |
| `ServiceName` | string | derived, not user-configurable | Set per-process by the composition root (`"Financial.Api"` / `"Financial.App"`) so traces from the two clients are distinguishable in the backend UI |

**Lifecycle**: read once at process startup, same as every other configuration value in this application (Constitution "Technology & Persistence Constraints" — config is not re-read at runtime; changing it requires a restart, per spec.md's edge-case note).

## Trace

A correlated record of one logical operation as it moves through the system. Not persisted by this application — owned entirely by the configured backend (Jaeger or Langfuse) for the lifetime of its container.

| Field | Notes |
|---|---|
| `TraceId` | Generated by the root `Activity` — ASP.NET Core auto-instrumentation for Web-originated requests, or the WPF command-layer root `Activity` for WPF-originated operations (FR-004a) |
| `Spans` | Ordered by start time; at minimum one span per: entry point (controller / WPF command), application-layer use case, storage operation |

**Validation rule**: every span other than a trace's root span MUST have a non-null parent span reference (enforced structurally by `Activity.Current` propagation, not by application code).

## Span

A single unit of work within a Trace.

| Field | Notes |
|---|---|
| `Name` | See naming convention in [contracts/telemetry-semantic-conventions.md](./contracts/telemetry-semantic-conventions.md) |
| `ParentSpanId` | Null only for a trace's root span |
| `Attributes` | MUST be limited to the allow-listed attribute set in the semantic-conventions contract (FR-014) — no raw financial values or PII |
| `Status` | Ok / Error, set when the operation throws |

## Log Record

A structured, timestamped event emitted via Serilog.

| Field | Notes |
|---|---|
| `Timestamp`, `Level`, `MessageTemplate`, `Properties` | Existing Serilog structured-logging shape, unchanged |
| `TraceId` / `SpanId` | NEW — populated by enrichment only when observability is enabled and an `Activity` is current; absent/empty when disabled |

**Validation rule**: log message templates and property values are subject to the same FR-014 redaction rule as span attributes — no raw financial values or PII as a logged property.

## Metric

A numeric measurement, not tied to a single request. Per FR-015, scoped to OpenTelemetry's standard ASP.NET Core / `HttpClient` / .NET runtime auto-instrumentation only (request count, request duration, error rate, GC/heap metrics, thread-pool metrics) — no custom business-domain metric instrument is introduced by this feature.
